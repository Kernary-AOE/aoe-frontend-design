# BorderRadiusDecision [pattern] v1.0.0
domain: frontend-design

## Label
Border Radius Decision Checklist

## Problem
Developers ship border-radius values without answering the underlying design intent question. The result is radius decisions that conflict with product personality or create visual inconsistency across component types.

## Solution
Before shipping, run a five-question checklist that forces articulation of product personality first, then validates radius consistency, interactive-element parity, nested-element adherence, and radius variation. If question 1 cannot be answered, stop and define personality before choosing any radius value.
